# VCT Connect browser capture

This is a local, unpacked Chrome extension for a buyer viewing a supported 1688 offer or Taobao item/shop. Clicking **Analyze this page** selects visible evidence and sends it to the signed-in VCT Connect account. For 1688, optional `https://*.1688.com/*` access lets a background job follow the product's supplier shop and its factory profile. Declining access keeps product-only analysis available. Taobao uses the existing `activeTab` capture path.

## Development setup

1. Put the existing Clerk publishable key in `frontend/apps/web/.env.local` as `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` (the web app already uses this file). Use the same Clerk development instance for web and extension.
2. From the repository root, run `npm install --prefix frontend --legacy-peer-deps`, then `npm run build --prefix frontend/apps/extension`.
3. Enable Clerk **Native API**. Register the extension's development origin by running `.\.venv\Scripts\python.exe scripts\configure_clerk_extension_origin.py` from the repository root. The script reads the ignored `.env.clerk`, preserves existing allowed origins, and registers `chrome-extension://klggcepemjjbphjclpiabgpfgdbgiljj`.
4. Add that exact origin to the backend's `CLERK_AUTHORIZED_PARTIES` alongside the web origin, then restart the backend. The repository's `.env.example` shows the format.
5. Open `chrome://extensions`, enable **Developer mode**, choose **Load unpacked**, and select `frontend/apps/extension/build`. Confirm Chrome shows extension ID `klggcepemjjbphjclpiabgpfgdbgiljj`.
6. Start the existing database, backend, and web app. The local extension build calls `http://127.0.0.1:3000`. A deployment build can set `VCT_WEB_ORIGIN` to its HTTPS origin before running the build command; the deployed backend must also allow the stable extension origin.

Open the extension and choose **Sign in on VCT Connect**. Complete sign-in in the web tab using the same Chrome profile, then return to a supported source page and reopen the popup. The popup checks the active page before exposing **Analyze this page**; signed-out or unsupported-page states never expose the enhanced-analysis action. Supported forms are `https://detail.1688.com/offer/<id>.html`, `https://item.taobao.com/item.htm?id=<id>`, and numeric `https://shop<id>.taobao.com` / `https://shop<id>.world.taobao.com` shops with `/`, `/index.htm`, or `/category.htm`. Tracking parameters are removed; duplicate item IDs, credentials, ports, fragments, mobile pages, Tmall, and short links are unsupported. Clerk Sync Host shares the web session with the extension. Development builds sync from the exact web origin (default `http://127.0.0.1:3000`); production builds sync from the Clerk Frontend API host. Do not use `localhost` when this build is configured for `127.0.0.1`.

Click **Analyze this page**. The action re-checks the active page identity and obtains a fresh Clerk token before any enhanced-evidence request. After capture is saved, the extension opens the web result in a new tab and loads the owner-scoped status through the shared VCT API client/contracts. **Open web result** remains available to reopen it. If result loading fails after submission, use **Reload last result**; the last analysis ID, source URL, and Clerk owner ID are stored locally so recovery is scoped to the signed-in account. If the source shows only a challenge or the chosen fields are absent, the result records a parse failure without a supplier snapshot.

After rebuilding, reload the extension from `chrome://extensions` before testing. Clerk's SDK uses the `cookies` permission to sync the VCT Connect session from the configured host; no source-site cookie is read. If the popup reports that sign-in is taking too long, open VCT Connect, confirm web sign-in completed, then close and reopen the popup.

For one-click 1688 collection, apply database migration `0017_extension_collection_jobs`, restart API and the continuous worker, and rebuild/restart the web app so its collection proxy routes are available. The job reserves one analysis and quota slot, captures the product and currently loaded reviews, then follows the shop and factory navigation. Only selected evidence is sent, capped at 32,768 UTF-8 bytes for the bundle. It verifies the product/shop/profile link chain and retains source URLs. Popup closure does not stop the background job; reopening restores owner-scoped collection progress. Created supplier tabs are closed after collection; the original product and web result remain open.

The server collection deadline is 60 seconds after reservation. If collection is interrupted, the running worker recovers the stored product and records linked pages as timed out. A denied permission, missing link, login/challenge, inaccessible page or timeout yields explicit partial evidence. LLM assessment may take longer than the collection deadline. Factory founding dates and company information remain platform claims; certificates and activity history stay unknown when absent. Photo/video analysis and additional review-page traversal are not included. A lost begin response preserves the same reservation ID for recovery instead of automatically reserving another analysis.

The 1688 selection retains its existing supplier, title, and price fields. Taobao items select the product title under ItemTitle/MainTitle, the shop name and contextual metrics, and review bodies under Comments/Comment/contentWrapper/content. Taobao shops select the shop name and at most 20 product links/titles inside the audited shop shelf. Inactive and hidden nodes are excluded; unverified shop age and evaluations remain unknown. Requests contain only source identity, optional canonical URL, and these selected values, within 16,384 UTF-8 bytes. Review text is bounded and its original extent is included. No source credentials, cookies, tokens, storage, full HTML, scripts, request headers, or page globals are read or sent. Results are labeled `EXTENSION_ENHANCED` / `EXTENSION_DOM` with user-provided browser provenance. Successful/partial captures queue assessment and reporting; configure the worker's server-only `YESCALE_API_KEY` for this path. The popup displays Risk, Confidence and Coverage only from an authorized persisted report. Missing reports and insufficient evidence never imply low risk. Reopening the popup restores the current owner's last analysis and loads its progress/verdict automatically; **Reload last result** remains a recovery action.

Saved HTML can also be imported through the signed-in web page using the matching supported source URL. Uploads are limited to 2,000,000 original bytes; 1688 requires UTF-8, while Taobao supports UTF-8 and GBK-family declarations. Conflicting or unsupported encodings are rejected. Uploads retain the original-byte hash, import time, and unknown original capture time, with `ACCOUNT_PUBLIC` / `USER_UPLOAD` provenance.

Successful/partial imports queue the same assessment/reporting path without recrawling the source page. Alibaba saved HTML and browser capture remain unsupported. See [the buyer acceptance guide](../../../END_USER_TEST.md) for concrete report/history/Watchlist and extension checks. Automated popup contracts do not replace a real Chrome/Clerk session-sync test.

If Windows reserves API port 8000, start Uvicorn with `--port 8080` instead. In the web app's PowerShell terminal, set `$env:API_INTERNAL_ORIGIN='http://127.0.0.1:8080'` before `npm run dev --prefix frontend`. The extension still uses web port 3000. Check reserved ports with `netsh interface ipv4 show excludedportrange protocol=tcp`.

The manifest's public `key` fixes the unpacked extension ID. It is not a signing key or a credential. Keep any private signing key for future store distribution outside the repository.
